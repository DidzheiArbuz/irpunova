## О проекте

Система на базе **Arduino Uno** контролирует освещённость, температуру и движение в помещении. Данные выводятся в Serial Monitor, записываются в журнал, обрабатываются Node-RED и загружаются в SQLite.

Для варианта 11 используются:

- LDR — датчик освещённости;
- NTC — температурный датчик;
- PIR — датчик движения;
- реле — исполнительное устройство;
- красный светодиод — индикация тревоги.

Аварийное событие возникает, если одновременно выполняются условия:

```text
PIR = 1 и освещённость < 30 %
```

При начале тревоги формируется событие `THRESHOLD`, включаются реле и светодиод. После исчезновения условия формируется `NORMAL`.

## Компоненты и подключения

| Компонент | Назначение | Подключение |
|---|---|---|
| Arduino Uno R3 | Контроллер | — |
| LDR | Освещённость | SIG/A0 |
| NTC | Температура | SIG/A1 |
| PIR | Движение | SIG/D2 |
| Релейный модуль 5 V | Исполнительное устройство | IN/D7 |
| Красный LED | Индикация тревоги | D13 через 220 Ω |
| Датчики и реле | Питание | VCC → 5V, GND → GND |

LDR подключён в делитель напряжения с резистором 10 kΩ. Точка между LDR и резистором подключается к A0.

## Период и формат данных

Период опроса в симуляции — 2 секунды, что ускоряет демонстрацию. В курсовом расчёте используется рабочий период 15 секунд.

Пример строки измерений:

```text
DATA n=3 s1=24.8 s2=22.4 s3=1
EVENT n=3 type=THRESHOLD
EVENT n=5 type=NORMAL
```

где `s1` — освещённость, `s2` — температура, `s3` — движение.

## Модель Wokwi

Проект симуляции находится в папке `sim/`:

- `sim/diagram.json` — схема соединений;
- `firmware/variant11.ino` — программа Arduino.

Чтобы создать публичную ссылку Wokwi:

1. Откройте Wokwi и выберите **Arduino Uno**.
2. Вставьте код из `firmware/variant11.ino` в `sketch.ino`.
3. Перенесите содержимое `sim/diagram.json` во вкладку `diagram.json`.
4. Нажмите **Save**, затем **Share**.
5. Скопируйте ссылку проекта в этот раздел README.

> Ссылка Wokwi: добавить после сохранения проекта кнопкой Share.

## Обработка данных Node-RED

Поток находится в `nodered/flow.json`.

Запуск:

1. Запустить Node-RED командой `node-red`.
2. Открыть `http://localhost:1880`.
3. Импортировать `nodered/flow.json`.
4. Проверить путь к `data/log.txt`.
5. Нажать **Deploy**.
6. Нажать кнопку загрузки журнала.

Поток читает `DATA` и `EVENT`, формирует SQL и сохраняет его в `db/load_runtime.sql`.

## SQLite

Создание и заполнение базы из корня проекта:

```text
sqlite3 db/variant11.db ".read db/schema.sql" ".read db/load.sql"
sqlite3 -header -column db/variant11.db ".read db/queries.sql"
```

В базе есть таблицы:

- `readings` — измерения датчиков;
- `events` — события `THRESHOLD`, `NORMAL` и `FAULT`.

## Проверка неисправности

Тестовый журнал с некорректным значением находится в `data/log_fault.txt`. При выходе показания за допустимый диапазон должна формироваться запись `FAULT` в таблице `events`.

## Python-скрипт

Дополнительная программная проверка находится в `python/monitoring_system.py`:

```text
python python/monitoring_system.py
```

Скрипт создаёт тестовые показания, события и базу SQLite. Основной вариант курсового проекта — Arduino/Wokwi, Python используется для дополнительной проверки обработки данных.

## Результаты тестирования

| Тест | Условия | Ожидаемый результат |
|---|---|---|
| 1 | PIR=0, LDR=20 % | Реле выключено |
| 2 | PIR=1, LDR=45 % | Тревоги нет |
| 3 | PIR=1, LDR=25 % | THRESHOLD, реле включено |
| 4 | После теста 3 PIR=0 | NORMAL, реле выключено |
| 5 | Значение вне диапазона | FAULT в SQLite |
